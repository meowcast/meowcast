# MEOW Pilot (phone web app)

A small React app that turns a phone into a remote for the dongle's launcher (`ui`). It
runs in two ways:

- **Served by the dongle.** `meow-netd` serves it on port 80 (from the initramfs,
  `/usr/share/pilot`), handles Wi-Fi setup and pairing, and sends the keys to the UI. On the TV's
  setup network it opens as a captive portal and shows the Wi-Fi setup: choose a network, then the
  password. On the home network it asks for the TV's pairing code (or takes it from the QR link
  `?pair=CODE`), then shows the remote with a Wi-Fi button. Details:
  [../../wifi/README.md](../../wifi/README.md).
  Stage a build for the firmware with `sh package-pilot.sh`, which writes `../../os/deploy/pilot`.
- **Served by the Mac** (development over USB, below). The Mac serves it on the local Wi-Fi and
  relays the keys to the dongle over USB.

The app tells the two apart by `/api/info`, which only the dongle answers.

```
phone ──WebSocket (LAN, token)──▶ Mac: server.mjs ◀──TCP (USB bridge)── dongle: remote-link.sh
                                                                         └─▶ /run/ui-keys ─▶ miracast-ui
```

The dongle *connects out* to the Mac (BusyBox `nc`), so it opens no listening port.
- **Web server:** binds only to the Mac's LAN address.
- **Dongle listener:** binds only to the Internet Sharing bridge (`bridge100`).
- **Pairing:** key presses need the pairing token (`?k=…`, stored in `.token`, shown as a QR code).

## Run

```sh
cd cloud/pilot
npm install            # once
npm run serve          # build + start; prints the phone URL and a QR code
```

On the dongle, once per boot, with the UI running (`/opt/ui/run.sh 1080p60 &`):

```sh
setsid /opt/ui/remote-link.sh >/dev/null 2>&1 </dev/null &
```

`remote-link.sh` ships in the UI package (`fetch ui/install.sh && sh /opt/install.sh`) and reconnects on
its own. The status pill on the phone shows:

| Pill | Meaning |
|---|---|
| Dongle connected | The Mac and the dongle link are both up |
| Waiting for dongle | The Mac is reachable, but `remote-link.sh` isn't running or the UI isn't up |
| Connecting to Mac… | The phone can't reach the server |

Server options: `--port 8080`, `--lan <iface>` (default: the default-route interface), `--usb bridge100`,
`--link-port 8002`. Set `REMOTE_TOKEN` to choose the token.

## Controls

| Control | Action |
|---|---|
| D-pad | Press, or hold to auto-repeat; OK in the centre |
| Touchpad mode (hand icon in the header) | Swipe moves one step per ~56 px; tap = OK |
| Back, Home | Back; Home closes the app on screen |
| Apps | The apps installed on the TV; tap one to open it there |
| Type | A text field whose content goes to the app on screen, with Delete and OK. Enabled while an app is on screen |
| ⏪ ⏯ ⏩ (while an app is on screen) | The app's `left`, `enter`, `right`: in YouTube back 10 s, play/pause, forward 10 s. They never move the launcher |
| Volume | Mute, − and + (hold to keep going), and a bar to drag. The number is the TV's own and follows changes made there |
| Keyboard (desktop testing) | Arrows, Enter/Space = OK, Backspace/Esc = Back, Home = Home |

The header shows what is on the TV and the connection: *Connected* with signal bars from the
heartbeat's round trip (≤ 180 ms three, ≤ 600 ms two), *Slow connection*, *Reconnecting…*, *TV is
offline*, *Phone is offline*, *Pair again*. A connection that stops answering is replaced after
11 s; controls stay in place, dimmed, until it is back.

Apps, Type, the media keys and the volume need firmware with pilot protocol 2
([../../wifi/README.md](../../wifi/README.md)); the TV lists what it can do (`caps`) and the app shows
only that. With older firmware it is the D-pad, Back and Home.

Android phones give a short vibration per key; iOS Safari has no vibration API. The screen stays
on while the remote is open (Screen Wake Lock).

**Home screen app.** `public/manifest.webmanifest` and the icons (`public/icon.svg`; PNGs made
from it with `qlmanage -t -s 512` and `sips -z`) make "Add to Home Screen" open it full-screen.
In cloud mode the address keeps the TV's id (`?d=`, not a secret), and the manifest has no
`start_url`, so the installed app starts at that address. On iOS an installed web app has its own
storage: it knows the TV but asks once for the pairing code (Settings › Wi-Fi › Pair a phone).
